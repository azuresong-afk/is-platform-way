# e2e единого входа

Playwright в настоящем браузере против стенда из `docker-compose.yml` с заглушками продуктов (`dev/fake-*`). У каждой заглушки есть своя крошечная страница, поэтому переходы между вкладками — это переходы между разными приложениями на одном origin, как в установке с настоящими продуктами.

| Сценарий | Что проверяется |
|---|---|
| Вход → все продукты | один вход в оболочке открывает «Сканер», «Устранение», «Аттестацию»; страница входа ни разу не появляется; новая вкладка входит тихим refresh; нет ошибок консоли и нарушений CSP |
| Вход со страницы продукта | `/vm/` без сессии → `/login?next=/vm/` → после входа обратно в продукт |
| Проект сохраняется | проект из шапки уходит в продукты через `?project=`, без него — из `localStorage`; переживает перезагрузку; смена в одной вкладке приходит в другую |
| Выход из продукта | открытые вкладки оболочки и продуктов уходят на вход сразу; новые вкладки не пускает; refresh — 401; повторный вход возвращает на ту же страницу |
| Ctrl+K по продуктам | результаты сгруппированы по продуктам, запросы и ссылки несут `?project=`, стрелка + Enter открывают результат; при `FAKE_GRC_DELAY_SECONDS=8` в окружении стенда и теста «Аттестация» получает «Не ответил за 3 с», а «Сканер» и «Устранение» отвечают быстрее 3 с |
| Выход из меню оболочки | то же для выхода из оболочки; «Назад» не возвращает в кабинет |
| Токен для API платформы (`platform-token.spec.ts`) | токен из `sessionStorage` получает 401 на `/api/platform/admin/*`, а экраны администрирования работают: оболочка ходит в API платформы с токеном `aud=["platform"]` из памяти, в хранилище браузера его нет; в запросах к продуктам (Главная, Ctrl+K, вкладки) нет токена с `platform` в `aud` |
| Команды (`teams.spec.ts`) | экран «Команды»: команда с ролями «Сканера» и четвёртого продукта `demo` (он подключён только переменными в `stack.env`), роль приходит в токен участника после refresh и уходит после исключения из команды; в шторке пользователя — команда и роли «из команды»; администратор не может вступить в команду с ролями (403 в API, недоступный флажок в экране). `TEAMS_SHOTS=<папка>` — скриншоты в обеих темах (в репозитории — `docs/screenshots/teams`) |
| Мгновенная блокировка (`block.spec.ts`) | у пользователя `e2e.blocked` открыта вкладка продукта; администратор отключает его — тот же access-токен за секунды получает `401 user_blocked` во всех четырёх продуктах (заглушки подписаны на `platform.user.blocked`, контракт v1.1, п. 6.5), перезагрузка уводит на вход; другие пользователи работают; после разблокировки новый вход снова пускает |
| Приёмка (`acceptance.spec.ts`) | общие критерии приёмки К1–К6 и пункты `docs/TESTING.md`, проверяемые через браузер и HTTP; итог — `docs/ACCEPTANCE.md` |

`acceptance.spec.ts` читает необязательные переменные: `ACCEPT_SHOTS=<папка>` — сохранить скриншоты в обеих темах (в репозитории — `docs/screenshots/acceptance`), `ACCEPT_SHOWCASE_URL` — адрес собранной витрины `@platform/ui` (иначе тест витрины пропускается), `ACCEPT_STOP_CMD` / `ACCEPT_START_CMD` — как остановить и запустить заглушку «Аттестации» для критерия «недоступный продукт» (иначе пропускается). Для комплекта (`deploy/suite.sh`) ещё `E2E_ADMIN_PASSWORD` — пароль администратора из его `.env`. Тест 5.7 делает срочную смену ключа подписи на стенде.

## Запуск

```bash
cd e2e
npm ci
npx playwright install chromium   # один раз
cp stack.env ../.env              # шлюз и API читают продукты из .env (сохраните свой .env, если он есть)
npm run stack:up                  # docker compose -p platform-e2e … --profile fakes up --build --wait
npm run e2e
npm run stack:down                # остановить и удалить данные стенда
```

Стенд слушает `127.0.0.1:18090` (переменные — `stack.env`, секреты там только для тестов). Другой адрес — `E2E_BASE_URL`. Данные (`E2E Альфа`, `E2E Бета`, пользователь `e2e.user` с ролями во всех продуктах) создаёт `tests/global-setup.ts`, пользователя `e2e.team` и команды с префиксом `E2E ` — `teams.spec.ts` через API администратора; повторный прогон на том же стенде их переиспользует.

В CI это джоб `e2e` в `.github/workflows/ci.yml`; при падении к запуску прикладываются отчёт Playwright, трассы и логи стенда.
