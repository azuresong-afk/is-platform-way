# e2e единого входа

Playwright в настоящем браузере против стенда из `docker-compose.yml` с заглушками продуктов (`dev/fake-*`). У каждой заглушки есть своя крошечная страница, поэтому переходы между вкладками — это переходы между разными приложениями на одном origin, как в установке с настоящими продуктами.

| Сценарий | Что проверяется |
|---|---|
| Вход → все продукты | один вход в оболочке открывает «Сканер», «Устранение», «Аттестацию»; страница входа ни разу не появляется; новая вкладка входит тихим refresh; нет ошибок консоли и нарушений CSP |
| Вход со страницы продукта | `/vm/` без сессии → `/login?next=/vm/` → после входа обратно в продукт |
| Проект сохраняется | проект из шапки уходит в продукты через `?project=`, без него — из `localStorage`; переживает перезагрузку; смена в одной вкладке приходит в другую |
| Выход из продукта | открытые вкладки оболочки и продуктов уходят на вход сразу; новые вкладки не пускает; refresh — 401; повторный вход возвращает на ту же страницу |
| Выход из меню оболочки | то же для выхода из оболочки; «Назад» не возвращает в кабинет |

## Запуск

```bash
cd e2e
npm ci
npx playwright install chromium   # один раз
npm run stack:up                  # docker compose -p platform-e2e … --profile fakes up --build --wait
npm run e2e
npm run stack:down                # остановить и удалить данные стенда
```

Стенд слушает `127.0.0.1:18090` (переменные — `stack.env`, секреты там только для тестов). Другой адрес — `E2E_BASE_URL`. Данные (`E2E Альфа`, `E2E Бета`, пользователь `e2e.user` с ролями во всех продуктах) создаёт `tests/global-setup.ts` через API администратора; повторный прогон на том же стенде их переиспользует.

В CI это джоб `e2e` в `.github/workflows/ci.yml`; при падении к запуску прикладываются отчёт Playwright, трассы и логи стенда.
