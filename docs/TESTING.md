# Ручная проверка этапа 1

Стенд: `cp .env.example .env`, заполнить секреты, `COOKIE_SECURE=false`, затем `docker compose --profile fakes up --build`. Кабинет — http://127.0.0.1:18090/. Автотесты (`pytest`, `vitest`) проверяют то же на уровне кода; этот список — для приёмки глазами.

## 1. Вход и сессия

| # | Действие | Ожидаемый результат |
|---|---|---|
| 1.1 | Открыть `/` без входа | Экран входа «Платформа» |
| 1.2 | Войти под администратором из `.env` | Главная с карточками «Сканер», «Устранение», «Аттестация» |
| 1.3 | Обновить страницу (F5) | Остаётся на Главной, повторного входа нет |
| 1.4 | Ввести неверный пароль 5 раз для одной учётной записи | «Учётная запись временно заблокирована»; верный пароль тоже не пускает 15 минут |
| 1.5 | «Пользователи» → заблокированный → «Снять блокировку» | Вход снова работает |
| 1.6 | Меню пользователя → «Выйти» | Экран входа; кнопка «Назад» в браузере не возвращает в кабинет |
| 1.7 | Открыть `/login?next=https://evil.example` и войти | Переход на Главную, а не на внешний адрес |

## 2. Пользователи и роли

| # | Действие | Ожидаемый результат |
|---|---|---|
| 2.1 | «Пользователи» → «Создать»: `petrov`, роль в «Устранении» — инженер, доступ к одному проекту | Пользователь в списке, роли показаны по продуктам |
| 2.2 | Открыть свою карточку администратора | Изменение своих ролей и проектов недоступно: «Разделение обязанностей…» |
| 2.3 | Войти под `petrov` | Видна только вкладка «Устранение»; на Главной — только её карточка; меню «Администрирование» отсутствует |
| 2.4 | Под `petrov` выбрать проект | Доступен только выданный проект |
| 2.5 | Администратором отключить `petrov` | Следующий запрос `petrov` получает 401, его открытая вкладка уходит на экран входа |

## 4. Продукты и Главная

| # | Действие | Ожидаемый результат |
|---|---|---|
| 4.1 | «Продукты» | Три продукта, статус «Работает», версия манифеста |
| 4.2 | Перезапустить с `FAKE_GRC_DELAY_SECONDS=8` | Карточка «Аттестация» — «Недоступен», остальные карточки и вкладки работают |
| 4.3 | Убрать `GRC_API_UPSTREAM` из `.env`, перезапустить | «Аттестации» нет ни во вкладках, ни на Главной, ни в «Продуктах»; `/grc/` переадресует на `/` |
| 4.4 | Ctrl+K, ввести «CVE» | Результаты из «Сканера» со ссылками в продукт |

## 5. Токены на стороне продуктов

Токен — из `sessionStorage` вкладки (DevTools → Application) или `POST /api/platform/auth/login`.

| # | Запрос | Ожидаемый результат |
|---|---|---|
| 5.1 | `curl :18090/api/vm/summary` без токена | 401 |
| 5.2 | Токен `petrov`, `GET /api/vm/summary?project_id=<его проект>` | 200 |
| 5.3 | Токен `petrov`, `GET /api/scanner/summary` | 403 `no_product_roles` |
| 5.4 | Токен `petrov`, `GET /api/vm/summary?project_id=<чужой проект>` | 403 `no_project_access` |
| 5.5 | `curl :18090/api/platform/.well-known/jwks.json` | Ключ `OKP`/`Ed25519` с `kid`; приватных полей нет |
